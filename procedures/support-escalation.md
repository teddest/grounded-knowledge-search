# Before escalating

The support agent records the workspace ID, customer impact, reproduction steps, relevant timestamps, request or invoice IDs, and the response already provided to the customer. Agents should search the current policies and product documentation before escalating routine questions.

# Finance escalations

Escalate billing issues to Finance Operations when they involve an exception request, suspected duplicate or unauthorized charge, a payment that succeeded externally but remains failed in Relay, or an amount above $1,000.

# Support Engineering escalations

Escalate to Support Engineering when a documented product action fails after one retry, a repeated export failure includes an export job ID, or the issue appears to be a product defect. Include browser or API details when available.

# Security and Privacy escalations

Escalate immediately for suspected account compromise, accidental exposure of personal data, a legal hold request, or a customer asking for a regulatory deletion determination. Do not include secrets or full payment-card numbers in a ticket.

# Customer communication

The agent tells the customer which team is reviewing the issue and provides the next update time. The agent must not promise a resolution date controlled by another team.
